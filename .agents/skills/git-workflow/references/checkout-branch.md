# 新建分支

基于当前分支生成规范的分支名；只有用户明确要求新建或切换分支且确认分支后，才创建并切换到新分支。

## 获取命名依据

优先根据用户描述的功能或修改目的命名。用户没有提供足够描述时，使用 `git status --short --branch`、`git diff --cached --stat` 和 `git diff --cached` 检查当前分支及暂存区改动。若两者都无法提供可靠依据，则询问用户要处理的内容，不要猜测。

## 命名规范

根据主要改动选择一个前缀：

- `feature/`：新增功能；
- `fix/`：修复问题；
- `docs/`：仅文档改动；
- `style/`：不影响逻辑的样式或格式调整；
- `test/`：测试改动；
- `refactor/`：不改变外部行为的重构。

前缀后的名称使用简洁、可辨识的英文小写 kebab-case，不使用中文。完整分支名（包含前缀和 `/`）不得超过 30 个字符。需求涉及多项改动时，以主要目的命名，不把所有细节拼入名称。

## 确认并创建

只需建议时，直接给出一个首选分支名，不修改仓库。用户明确要求新建分支时，先展示完整分支名并明确询问是否接受；收到肯定答复后，确认名称满足规范且本地不存在同名分支，再基于当前分支执行：

```bash
git checkout -b feature/add-new-feature
```

将示例名称替换为实际分支名。若用户不接受，则按反馈修改并再次确认，不得在确认前创建或切换分支。若同名分支已经存在，不覆盖或删除它；说明冲突并提供新的候选名，获得用户确认后再创建。
